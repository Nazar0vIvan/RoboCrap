# Prepare and animate planar probe scans on a placed workpiece

## Purpose / Big Picture

In **Measuring / Precise**, **Refine Frame** opens Properties so the operator can choose three CAD faces on a roughly placed workpiece, define a grid of probe contacts on each and save the definition as a **Refine Job**. Selecting that job and pressing **Generate Path** creates a linked **Scan Path**. Selecting the path and pressing **Dry Run** animates the existing on-screen robot. The first workpiece is the GE-22 end gauge. Calibration uses a separate fixed two-face measurement on that gauge.

This is a living ExecPlan. Maintain Progress, Surprises & Discoveries, Decision Log and Outcomes & Retrospective at each stopping point. The deliverables are the editor, path generation, disconnected playback and the common numerical input used by calibration sampling. Physical scanning means touching points using KUKA’s Robot Sensor Interface (RSI). Starting a new standalone controller procedure, fitting its returned observations and accepting a refined placement are subsequent work. A generated path alone never changes the active workpiece placement.

## Surprises & Discoveries

5b, 2026-11-26. The saved GE-22 mounting identifies the exact bytes of the observation file. The deployed CRLF copy had the same observations but a different digest. Converting only the disposable copy to LF recovered the saved mounting digest. The scene then resolved the reloaded job and its CAD normally.

Milestone 5 planning (2026-11-26). The fixed GE-22 factory already offsets planar contacts by the ruby radius and the 3 mm search gap. The step builder, motion solver and sampler already implement the approach, retract and missed-trigger allowance. Their existing face and purpose labels distinguish only sphere calibration, verification and the fixed two-face gauge. Three saved CAD roles need their own identities at these boundaries.

4d. The version 1 store contains a mounting digest, source BREP digest, full placement and process-local workpiece ID. Loading jobs before inserting the gauge can allocate the gauge's old ID to a job. Two placements can also share both digests. Reopening therefore uses the current live instance when known, requires a unique match after restart, and offers the Object picker when the match is ambiguous.

4c. The interrupted tree already contained the two-argument scene operation, CAD checks, versioned writer and job properties. The Create button was permanently disabled, ScenePanel had no group for the job kind, and its Properties type label was empty.

4b. The native window and the main QML window have separate Delete handlers. Disabling only the QML shortcut leaves a native viewport click followed by Delete able to reach scene deletion. Both input paths must recognize point picking.

4a. A planar BREP can use spline parameters with units that differ from millimetres. Compute the grid from the extrema of trimmed boundary edges in the workpiece plane, then project physical points onto the source surface for trim classification. The four margin fields run left, top, bottom, right, corresponding to −U, +V, −V, +U.

3d. Source BREP faces can carry their own locations. Moving the entire BREP before constructing its AIS shape changes the locations used in face lookup. Keeping the native shape and applying the same mounting transform to its AIS presentation preserves the source map, including repeated subshapes at different locations. The deployed GE-22 STEP contains six plane surfaces; the curved-face check needs a different scratch solid.

2026-11-25, 3c. The GE-22 loader retains one scene ID. Its observations digest describes the mounting input, while the loaded BREP has a separate content revision. Two copies can share both digests. The native background-click handler also cleared OCCT selection before the workspace received the miss. The workspace already updates drawing selection after an ordinary miss, so the input handler now reports it without clearing the highlight itself.

The list of animation phases already exists. In `src/trajectories/probe/probetouchmotion.cpp`, `probeMotionSteps` orders moves and `TouchMotionBuilder::append` constructs each movement. In `src/trajectories/probe/probersistream.cpp`, the sampler pairs that sequence with the saved motion phases. Before Milestone 1 both implementations interpreted Transfer as a sphere arc. They now consume the movement kind stored on each ordered step. Production sampling still accepts only the sphere procedure.

The viewer already detects model faces. In `src/viewport/occt/occscene.cpp` imported shapes can enable face, edge and vertex detection. `OccViewport::mousePress` in `src/viewport/occt/occviewport.cpp` reduces the pick to an object ID or tool flag. `OccViewWindow::mousePressEvent` then emits the corresponding selection request. That loses the identity and local geometry of the selected face. Milestone 1 replaced the Precise toolbar’s local playback flags in `src/application/qml/Main.qml` with the owning path and player state. Face picking remains for Milestone 3.

The deployed GE-22 boundary representation (BREP, the model’s faces, edges and their boundaries) comes from the existing STEP CAD conversion using `tools/cadstep2brep`. Its measured placement and model drawing already share one scene object. Calibration and Precise now share the same gauge. Opening either submode reloads it. Identical source and placement reuse its scene object ID. Replacing or removing the gauge invalidates the scan. A draft can open without a selection. Assigning faces requires a placed model.
