# EG22 — чек-лист приёмки на роботе

Основание: `plans/EG22_PRECISE_SCAN_EXECPLAN.md` из снимка `RoboCrap-snapshot-20261128-011124980.zip`. M1–M4 реализованы; доступные офлайн-проверки M1–M3 пройдены, M4 пока имеет только проверку исходников. Этот документ — операторский чек-лист, не новый ExecPlan и не разрешение на движение робота.

Цель: подтвердить цепочку RSI Sampling → Scan → фактические касания → расчёт {Wr} → Scan complete → Cancel/Reassign → восстановление принятого положения после перезапуска.

Пути ниже предполагают рабочий компьютер с проектом `E:\Qt\QtProjects\RoboCrap` и стандартными `ROBOCRAP_SETTINGS_DIR` / `ROBOCRAP_RECORDS_DIR`. При другом расположении используй фактические пути из конфигурации сборки.

## 1. Подготовить одно рабочее задание (M1–M2)

Выполнять физическую часть только после пункта 0. При первой проверке использовать ранее проверенную конфигурацию сетки и одну группу ориентации, например G2, если она подходит установленному щупу и подтверждена для работы.

- [ ] В RoboCrap: Edit → Settings → Network. В списке Device выбрать соответствующий профиль PLC, проверить адреса/порты и Connect. Аналогично выбрать профиль RSI и Connect. В таблице Connections проверить состояние обоих соединений. Для RSI состояние Connected означает готовность сокета, а не само по себе подтверждение работоспособности контроллера.
- [ ] В соответствии с действующей процедурой ячейки подготовить CELL к AUT EXT. В RoboCrap открыть Views → PLC Panel. Убедиться, что имеется свежая обратная связь, контроллер готов к новому заданию: AUT EXT и IN_HOME активны, APPL_RUN выключен; последовательность выбора программы PLC в IDLE. Не запускать при неизвестном состоянии предыдущей программы, ошибках или отсутствии допуска.
- [ ] В Workflow выбрать Measuring → Precise. В Scene → Refine Jobs выделить существующий Refine Job с тремя правильными гранями EG22. Нажать Generate Path → Group (согласованная G1/G2) → Generate. Выбрать созданный объект в Scene → Scan Paths.
- [ ] Нажать Dry Run для визуальной проверки маршрута с применённым TCP. Дождаться окончания анимации. При сомнении в физических зазорах не продолжать.
- [ ] Нажать RSI Sampling. Для прежней неизменённой сетки ожидать `RSI Sampling: 31 touches · 100 steps`, поле Sampled job в Properties. Если сетка изменилась, использовать фактическое число включённых контактов. Записать ID задания. Кнопка Scan должна стать доступна только при выполнении всех условий, Resume остаётся неактивной.
- [ ] Открыть `records` и последнюю папку `_scan` с `session.json`, `outcome: sampled`. Сверить `job_id` с Sampled job, `inputs.measuring_setup.primary`, непустые `inputs.pose_bounds` с basis, `inputs.compensation_radius_mm` и отсутствие `scan_setup_error`. Проверить наличие `C:\RoboCrapJobs\scan_data.txt`. Повторно пересчитывать все команды вручную не нужно: M1 уже принят.

Если Scan недоступен, не обходить проверку. Зафиксировать статус, состояния PLC/RSI и прислать sampled `session.json`. При наличии `settings/scan_in_progress` не удалять маркер вручную: он защищает от замены потенциально активного задания после перезапуска.

## 2. Первое сканирование — проверка M2 и M3, затем Cancel (M4)

- [ ] После разрешения ответственного оператора нажать Scan. Следить за движением и состоянием ячейки из безопасного положения. В статусе ожидается `Scan: … % · …/31 touches` для прежней сетки. Не изменять TCP, настройки, Refine Job, файлы задания или подключения во время работы. При любой опасной/неожиданной ситуации остановить работу по утверждённой процедуре ячейки.
- [ ] Дождаться полного завершения и подтверждённого возврата HOME. Проверить, что робот выполнил все контакты, а не только сообщил Finished. После успешной записи архива должно открыться **Scan complete**. До выбора Reassign модель EG22 и стойка остаются в старом положении.
- [ ] Сделать скриншот окна. Проверить наличие двух компактных блоков: Translation (ΔX, ΔY, ΔZ в мм) и Rotation (ΔA, ΔB, ΔC в градусах), кнопок Reassign и Cancel. Смещения показаны относительно прежней СК концевой меры, а не осей базы. Не ожидать произвольного заранее заданного диапазона. Не применять явно необъяснимый результат.
- [ ] Нажать Cancel. Окно закрывается; положение и ориентация EG22, положение стойки и ранее принятые измерения не меняются. `EG22_precise.json` не создаётся, если его не было, либо остаётся прежним побайтно. Архив реальных измерений сохраняется. Старый sampled job не должен быть повторно запускаемым без нового RSI Sampling.
- [ ] В `records` найти папку именно выполненного сеанса `_scan` (отличить от sampled по `outcome`). В `session.json` успешный сеанс имеет `kind: scan`, `outcome: ok`, совпадающий job_id, `result.workpiece_in_base` и `result.plane_residuals`. В `scan_completion.json` ожидаются `acknowledged`, `observed_low`, `observed_high_after_low`, `terminated` = true; HOME/Finished в `terminal_plc`, поле `error` пустое. В `touches.csv` и `observations.csv` по 31 строке данных для прежней сетки, не считая заголовка; номера 1–31. Если сеанс failed, не должно быть окна успешного применения; сохранить имеющиеся измерения и сообщение ошибки.

Сохрани полный ZIP выполненного сеанса и, если возможно, его sampled-сеанс. Подробную сверку `plan.csv`, фактических углов сочленений, координат, эффективного радиуса, невязок и матриц я выполню по этим файлам; вручную пересчитывать 31 точку не требуется. Невязки диагностические: в плане нет установленного нового порога по ним.

## 3. Второе сканирование — Reassign (M4)

Переходить только после подтверждения корректности первого измерения и пригодности результата для применения.

- [ ] Снова выбрать актуальную траекторию в Scene → Scan Paths (или заново Generate Path, если она аннулирована). Выполнить новый RSI Sampling, убедиться, что ID задания новый. Повторить допуск и визуальную проверку, если изменилась траектория или конфигурация. Выполнить разрешённый Scan и дождаться Scan complete.
- [ ] Сфотографировать/сохранить значения ΔXYZ/ΔABC. Проверить достоверность результата; затем нажать Reassign. При ошибке сохранения не повторять физическое сканирование только ради записи файла: зафиксировать сообщение. При `Scan archive failed` существующее окно предлагает Retry для записи и Cancel для отказа; это не повторный запуск робота.
- [ ] Убедиться, что EG22 принимает новое положение и ориентацию; стойка следует за началом СК без поворота. При малых смещениях визуально они могут быть незаметны — тогда сравнение матриц и файла надёжнее картинки. Refine Job сохраняется с прежними UUID, ревизией, гранями и сеткой; прежние пути, привязанные к старому положению, больше не пригодны для запуска.
- [ ] Открыть `settings/EG22_precise.json`. Должны появиться `source: measured`, `job_id` принятого результата, `session_folder` соответствующего выполненного сеанса, `expected_counts: [16,9,6]` для прежней сетки, 31 запись `observations`, `compensationRadiusMm`, `physicalBallRadiusMm`. При принятии EG22 не должны меняться грубые измерения, параметры щупа или определение Refine Job.
- [ ] Если после сохранения показано `Measurements saved; scene placement unavailable`, это не потеря измерений: precise-файл уже принят, старое отображение может остаться. Не запускать физические операции с EG22; сохранить ошибку, устранить причину и восстановить сцену через повторный вход в режим/перезапуск по безопасной процедуре.

## 4. Перезапуск и проверка нового положения

- [ ] Убедиться, что физическое задание завершено, никаких активных движений или неподтверждённой остановки нет. Закрыть RoboCrap и открыть его снова, соблюдая процедуру контроллера.
- [ ] Перейти в Measuring → Precise, затем Calibration и обратно. EG22 и стойка должны сохранять принятое после Reassign положение, а не возвращаться к rough. Непринятый результат предыдущего Cancel не должен применяться.
- [ ] Проверить, что старый Refine Job доступен. Создать новый Scan Path из него и выполнить RSI Sampling без нового физического запуска. В новом sampled `session.json` поле `inputs.gauge_workpiece_in_base` должно соответствовать принятому `result.workpiece_in_base` предыдущего выполненного сеанса (с учётом точности сериализации). Это подтверждает, что новая траектория использует уточнённую СК. Если изменившееся положение не позволяет построить допустимую траекторию, сохранить диагностику, а не обходить ограничения.

## 5. Отдельные проверки отказов — после нормального цикла, по разрешению

Не включать эти проверки в первый движущийся запуск и не создавать опасных ситуаций, не провоцировать коллизии, отказ оборудования или срабатывание аварийного останова. Использовать существующие записи, безопасный согласованный режим проверки или отдельное разрешение на соответствующее испытание. Если доказательств нет, оставить пункт pending.

- [ ] Изменённый/отсутствующий `scan_data.txt` после Sampling: проверка SHA-256 должна отказать до запроса программы 2. Проверять только с гарантированно исключённым физическим движением по утверждённой процедуре; иначе отложить. После отказа требуется новый Sampling.
- [ ] Штатно разрешённое прерывание/Resume: продолжение сохраняет тот же job_id и один сеанс; отказ Resume не уничтожает сеанс. Проверять только по согласованной процедуре PLC/smartPAD, не имитировать сигналы готовности.
- [ ] Досрочный выход/неполные касания: сеанс failed, доступные касания сохранены, Scan complete не открывается и действующий precise-файл не меняется. Finished без свежего low/high и всех касаний недостаточен. При наличии фактического случая проверить, что после аннулирования запрещены дальнейшие RSI-коррекции и замена задания вплоть до подтверждённого завершения программы. Не удалять маркер `scan_in_progress`, не использовать изменение режима как обход блокировки.
- [ ] Закрытие Scan complete крестиком: эквивалент Cancel. Проверить при следующем подходящем успешном сеансе, не назначать дополнительное движение только ради проверки крестика. Ошибки записи/вставки CAD и повреждённый precise-файл проверять позднее без движения по отдельной безопасной процедуре, если они не возникли сами; не портить рабочие settings.
