# RoboCrap run records

RoboCrap writes run records under `ROBOCRAP_RECORDS_DIR` (CMake cache path, default `records/` in the repository). The same CSV headers are used by the application, `python/records/convert_records.py` and the offline analysis scripts.

## Terms

- A calibration session covers one **Start Calibration** request, including interruptions and resumes. For chamfer (`RSI_Chamfer_Hole`) and test LIN (`RSI_Probe_Check`), each recorded RSI capture forms a session.
- **Calibration RSI Sampling** computes the sphere and gauge search streams and saves the planned job in a timestamped calibration folder. Both synthetic and measured placements use this operation. The status bar shows the saved path. Chamfer sampling exports its KRL job to `C:/RoboCrapJobs/` and keeps the plan for the run. **RSI test LIN** installs fixed increments.
- `job_id` in `session.json` identifies the sampled correction table (`diagnosticId`, based on UTC). Separate sessions can use the same table.
- The controller sends an XML request every 4 ms while RSI is on. The PC answers the newest valid request it read. IPOC is the controller's millisecond counter, normally increasing by 4 per cycle.
- The PC timestamps requests, replies and PLC observations with `recordClockNs()`, using `std::chrono::steady_clock`.

## Session start, end and writing

**Sampling record.** Calibration sampling writes `plan.csv`, `calibration_data.txt` (the serialized step table) and `session.json` with `outcome` set to `sampled`. The local start timestamp marks the save and `duration_s` is zero. Detections, PLC observations, RSI packets and fitted results belong to an executed session. Controller delivery for combined calibration is deferred.

**Calibration run.** The session starts before the application sends PLC program 1. A Passive STOP and Resume share the original session. Program completion, a detected start failure, leaving AUT EXT, PLC disconnection, job invalidation or application shutdown ends the run. Closing requests the remaining capture. If the flush acknowledgement is still missing after the 2 s wait, the recorder writes the available data with an error. RSI traffic for an armed calibration outside an open session is reported and skipped.

**Chamfer and test LIN.** The recorded interval runs from the first to the last stored request. `RsiDevice` flushes after at least 1 s since the last stored request (checked every 250 ms), on table replacement, disconnect or shutdown. The recorder writes a nonempty capture only if its job ID still matches the armed job when delivered. Another exchange using the same job can produce another folder. Approach and retreat outside RSI are outside the recorded interval.

**Writing.** With a table installed, `RsiDevice` stores accepted-peer XML before protocol decoding. Each capture can hold 262,144 requests and 128 MiB of request XML. Excess requests increment `rsi.dropped`. The receive callback performs protocol decoding and reply encoding. After close, a separate worker decodes stored XML for the CSVs and commits files individually with `QSaveFile`, `session.json` last. A write error can leave a partial folder. Data still held in memory can be lost on abnormal exit.

## Folder name

`yyyy-MM-dd_HH-mm-ss_<kind>`, followed by `_failed` when the session failed, for example `2026-11-20_16-58-26_calibration` or `2026-11-21_10-04-51_chamfer_failed`. The time is the local time of the session start; `<kind>` is `calibration`, `chamfer` or `test-lin`. When a folder of that name exists, `_2`, `_3`, … is appended. A calibration session fails when its run error is not empty (start failure, PLC disconnect, missing touches, fit or settings error); a chamfer or test LIN session fails when the correction stream did not reach its end (Result 1 echoed by the controller).

## Files

| File | Kinds | Content |
| --- | --- | --- |
| `session.json` | all | what, when, outcome, inputs, result, RSI summary |
| `plan.csv` | calibration, chamfer | One row per planned touch, or the initial pose and one row per chamfer motion increment |
| `calibration_data.txt` / `shared_data.txt` | native calibration / chamfer | Serialized job bytes for the sampled or executed job |
| `rsi.csv` | with a capture | One row per stored request, with reply fields when a send was attempted |
| `rsi_timing.csv` | with a capture | PC timing for the same requests in the same order |
| `plc.csv` | with PLC rows | Available state at session start and observations through session end |
| `touches.csv` | calibration with detections | Joint angles per detected touch |
| `residual_sets.csv` | calibration with a computed fit | Step-K7 residual sets |

Manual force sensor logs (`fts_*.json`) go directly under the records root.

## CSV conventions

CSV files use UTF-8 without a BOM, a semicolon separator, a decimal point and a single header. In pandas use `sep=";"`. Units appear in column names (`_s`, `_mm`, `_deg`, `_us`). Flags generated by the writer use `0` or `1`. Native `t_s` is signed elapsed PC time in seconds from session start, printed to six decimals. Cartesian A, B, C are principal Z-Y-X Euler angles and may wrap. Compare rotation matrices for orientation.

## session.json

JSON indented by 4 spaces, top-level keys in this order, keys inside `inputs`, `result` and `rsi` in alphabetical order (the `//` remarks explain the example and are not part of the file):

    {
      "format": 1,
      "kind": "calibration",                       // calibration, chamfer or test-lin
      "krl_program": "RSI_Probe_Calibration",
      "start": "2026-11-20T16:58:26.391+03:00",    // local time of t_s = 0 with UTC offset
      "duration_s": 1001.234,
      "outcome": "ok",                             // sampled, ok or failed
      "error": "",                                 // the run error when failed
      "job_id": "calibration_20261120_135817_781",
      "inputs": { ... },
      "result": { ... },                           // calibration with outcome ok only
      "rsi": {"delayed": 30, "dropped": 0, "max_delay": 6, "requests": 132812, "unanswered": 103, "unreadable": 0}
    }

`rsi` is present when the writer receives capture data. `requests` counts stored requests. `unanswered` counts rows without a send attempt, including superseded or protocol-invalid requests. `delayed` counts positive controller Delay D values and `max_delay` is the largest observed value (zero when none is positive). `unreadable` counts requests whose XML yields no decoded elements. `dropped` counts requests omitted by the capture limits.

`inputs` of a calibration session: `tool_xyzabc` (flange-to-TCP X, Y, Z in mm and A, B, C in deg, as sent to KRL), `sphere_centre_b_mm` (3 values), `sphere_radius_mm`, `ball_radius_mm`, `strut_radius_mm`, `strut_recess_mm`, `search_feed_mm_s`, `transfer_feed_mm_s`, `transfer_acceleration_mm_s2`, `touches`, `steps`.

`inputs` of a chamfer session: `path_name`, `tool_xyzabc`, `chamfer_size_mm`, `chamfer_angle_deg`, `flip_axis`, `staging_distance_mm`, `lead_in_clearance_mm`, `lead_in_span_deg`, `lead_out_clearance_mm`, `lead_out_span_deg`, `machining_feed_mm_s`, `acceleration_distance_fraction`, `transfer_feed_mm_s`, `transfer_acceleration_mm_s2`, `staging_joints_deg` (6 values), `joint_speed_limits_deg_s` (6 values), `phase_end_times_s` (3 values: end of lead-in, machining and lead-out), `cycle_s` (0.004), `settle_zero_cycles` (50).

`inputs` of a test LIN session: `direction` ("WORLD +X"), `step_mm` (0.004), `cycles` (25000), `settle_zero_cycles` (50).

`result` of a successful calibration session: `ball_centre_f_mm` (3 values, ruby ball centre in the flange frame {F}), `sphere_centre_b_mm` (3, sphere centre in the base frame {B}), `verification_sphere_centre_b_mm` (3), `contact_vertical_mm`, `contact_horizontal_mm`, `quantile95_mm`, `repeatability_mm`, `smallest_singular_value`, `calibration_touches`, `verification_touches`, with floating-point results rounded to six decimal places. The settings file `settings/probe_calibration.json` stores the base session name (before any folder collision suffix) as `lastCalibration.id`.

A converted session (made from records older than this format) adds `"converted_from": "<old folder name>"` and `"clock": "rsi and plc times have separate origins"`, and its `inputs` contain only `touches` (the other inputs were not recorded). Its session start is the PLC `run` row of that run, its `rsi.csv` and `rsi_timing.csv` count `t_s` from the first stored request, and `duration_s` is the time from the first to the last request; `y1_7_probe` and `y2_0_spindle` are empty (not in the old PLC logs). The converter has no original KRL job bytes to archive. Successful converted sessions can have `null` in `error`.

## plan.csv

Calibration, one row per touch:

    touch;search_step;purpose;group;repetition;pass_touch;tilt_deg;roll_deg;normal_x;normal_y;normal_z;start_x_mm;start_y_mm;start_z_mm;start_a_deg;start_b_deg;start_c_deg;contact_x_mm;contact_y_mm;contact_z_mm;contact_a_deg;contact_b_deg;contact_c_deg;start_s;start_t;face;face_point

`touch` is the global touch number (the RSI TouchIndex), `search_step` the 1-based step of the search in `calibration_data.txt`, `purpose` `calibration`, `verification` or `gauge`, `group` the probe orientation (1 stylus down, 2 stylus along +X, 3 stylus down turned 180°), `repetition` the pass of that group, `pass_touch` the touch within the pass, `tilt_deg`/`roll_deg` the touch direction, `normal_*` the outward surface normal at the contact, `start_*` and `contact_*` the nominal ball-centre poses at the search start and at contact, `start_s`/`start_t` the KUKA Status/Turn at the search start. Combined sessions append `face` (A or B) and `face_point` (1–4) for gauge rows. Sphere rows leave both fields empty. Earlier sphere-only sessions omit these two columns.

Combined sessions store `gauge_length_mm`, `gauge_reference` (nominal for the GE-22 preset), `gauge_source`, `gauge_observations_sha256` and `gauge_workpiece_in_base` (four matrix rows, translation in mm) in `session.json` inputs. Run `python python/calibration/calibration_analysis.py gauge <session folder>` for measured length and effective ball radius by probe orientation.

Chamfer starts with the initial pose at `time_s` 0 and a zero increment. Motion increment `i` belongs to row `i + 1` when counting from row zero. The settling zeros are specified in `inputs.settle_zero_cycles` and have no plan rows.

    time_s;target_x_mm;target_y_mm;target_z_mm;target_a_deg;target_b_deg;target_c_deg;a1_deg;a2_deg;a3_deg;a4_deg;a5_deg;a6_deg;increment_x_mm;increment_y_mm;increment_z_mm;increment_a_deg;increment_b_deg;increment_c_deg

`time_s` is the plan's time since the lead-in start (planned, not the record clock); `target_*` is the analytical TCP target, `a*_deg` the joint angles of the TCP reconstructed from the rounded increments, `increment_*` the correction sent in that cycle.

## rsi.csv

One row per stored request in receive order:

    t_s;ipoc;start;result;touch_index;touch;delay;rist_x_mm;rist_y_mm;rist_z_mm;rist_a_deg;rist_b_deg;rist_c_deg;a1_deg;a2_deg;a3_deg;a4_deg;a5_deg;a6_deg;stream_index;corr_x_mm;corr_y_mm;corr_z_mm;corr_a_deg;corr_b_deg;corr_c_deg;stop;reply_result;xml_base64

`ipoc` through `a6_deg` contain decoded XML values, including literal controller text such as `not linked:3`. When there is a send attempt, `stream_index` is the device index before processing the request, the six `corr_*` values use six decimals, and `stop` and `reply_result` are integers. Without a send attempt these columns are empty. When XML decoding returns no elements, request fields are empty and `xml_base64` preserves the request bytes. Other XML elements, including `MACur`, have no CSV columns.

## rsi_timing.csv

The same rows in the same order:

    ipoc;t_s;entry_us;sleep_us;wake_us;prev_done_us;reply_us;write_us;write_bytes

All `_us` columns except `write_us` are offsets in microseconds (one decimal) from the row's receive time `t_s`, negative when earlier: `entry_us` start of the receive handler, `sleep_us` and `wake_us` the last sleep and wake of the `ControlIO` event loop before the handler, `prev_done_us` the end of the previous replying handler, `reply_us` the call of `writeDatagram`. `write_us` is the duration of that call and `write_bytes` its result (−1 on failure). The handler columns are filled only on answered rows. Receive times are the moments the application dequeued the datagram, not network arrival times.

## plc.csv

    t_s;event;x1_0_aut_ext;x1_2_peri_rdy;x1_3_stopmess;x1_4_pro_act;x1_5_pgno_req;x1_6_appl_run;x1_7_in_home;y1_0_ext_start;y1_1_drives_on;y1_2_conf_mess;y1_3_pgno0;y1_4_pgno1;y1_7_probe;y2_0_spindle;step;program;result

When a PLC observation exists at or before session start, the recorder copies the latest one into a `state` row at `t_s` zero. It then includes observations through session end. `io` records a change in an X1, Y1 or Y2 mask, step, program number or result. Other native events include `run <n>`, `resume`, `reply timeout <transaction>`, `read error <code> frame <hex>`, `unmatched reply <transaction>` and `error cmd=<command> code=<code>`. Converted logs can include `abort`.

X1 inputs report KR C4 outputs. Y1.0–Y1.4 drive Automatic External inputs, Y1.7 copies the probe signal to `$IN[8]`, and Y2.0 controls the spindle inverter. `step` encodes IDLE, PREP, START or SELECT, `program` is the requested number, and `result` encodes `-`, STARTED, RESUMED, TIMEOUT, ABORTED or AUT_EXT_LOST. Unknown step and result codes are written as numbers. PLC rows use the PC observation time. The 2 s heartbeat can recover the current state after a lost change frame. Transient edges between observations can be missed. See [ARCHITECTURE.md](ARCHITECTURE.md).

## touches.csv and residual_sets.csv

`touches.csv` has header `touch;a1_deg;a2_deg;a3_deg;a4_deg;a5_deg;a6_deg`. Each row holds the first reported detection for that touch in run order. The RSI request must decode with Start 1, Touch 1, a positive TouchIndex and six joint angles. The writer prints the angles in degrees to six decimals. Failed runs retain their detections.

`residual_sets.csv`: `set;group;value_deg;mean_mm;bound_mm;count`, one row per step-K7 set of `docs/calibration/ROBOT_PROBE_SPHERE_CALIBRATION_METHOD_RU.md`: `set` is `ring` (equal tilt) or `roll` (equal roll), `value_deg` that tilt or roll, `mean_mm` the mean calibration residual, `bound_mm` = 3·repeatability/√count.

`python -I python/calibration/calibration_fit.py records/<folder>` recomputes the result from `plan.csv` and `touches.csv` and prints the differences to `session.json` "result" and `residual_sets.csv`.
